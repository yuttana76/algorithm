1. โจทย์คลาสสิกอันดับ 1: TWO SUM
--------------------------------------------------------------------------------
- โจทย์: กำหนดลิสต์ตัวเลข nums (ไม่ได้เรียงลำดับ) และค่าเป้าหมาย target
  จงคืนค่า index ของตัวเลข 2 ตัวที่บวกกันได้เท่ากับ target
  (เงื่อนไข: ห้ามใช้ตัวเลขตำแหน่งเดิมซ้ำ 2 ครั้ง)
- ตัวอย่าง: nums = [2, 11, 7, 15], target = 9  ->  Output: [0, 2] (เพราะ 2 + 7 = 9)


2. วิธีที่ 1: BRUTE FORCE (วิธีคิดตรงไปตรงมา - ลองจับคู่ทุกคู่)
--------------------------------------------------------------------------------
- แนวคิด: ใช้ลูปซ้อน 2 ชั้น หยิบเลขตัวแรก (i) มาบวกกับตัวที่อยู่ข้างหลังทีละตัว (j = i + 1)
- ทำไมต้องรู้จัก Brute Force?
  ในห้องสัมภาษณ์ การเริ่มพูดวิธี Brute Force ก่อนช่วยให้ผู้สัมภาษณ์เห็นว่าคุณเข้าใจโจทย์
  แล้วค่อยโชว์สกิล Optimize ให้เร็วขึ้นด้วย Hash Map

[โค้ด Brute Force]
def two_sum_brute_force(nums: list[int], target: int) -> list[int]:
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, n):            # เริ่มที่ i+1 กันจับคู่ตัวเดิมและกันเช็กซ้ำ
            if nums[i] + nums[j] == target:
                return [i, j]
    return []

- Time Complexity  : O(n^2) (ลูปซ้อน 2 ชั้น -> ช้ามากเมื่อ n ใหญ่!)
- Space Complexity : O(1)


3. รู้จัก HASH MAP (dict) และ HASH SET (set) ใน PYTHON
--------------------------------------------------------------------------------
- เปรียบเทียบความเร็วในการค้นหา (Lookup):
  * list        : เหมือนสมุดจดเบอร์เรียงมั่ว -> ต้องไล่หาทีละบรรทัด -> O(n)
  * dict / set  : เหมือนตู้ล็อกเกอร์ที่มีป้ายชื่อ -> รู้ key เดินตรงไปเปิดได้เลย -> O(1)!

- ต่างกันอย่างไรระหว่าง dict (Hash Map) กับ set (Hash Set)?
  * dict -> เก็บคู่ {key: value} ใช้เมื่อต้องการจำ "ข้อมูลเสริม" เช่น index หรือจำนวนนับ
  * set  -> เก็บแค่ {key} ใช้เมื่อต้องการเช็กแค่ว่า "เคยเห็นแล้วหรือยัง" (เช่น เช็กค่าซ้ำ)


4. วิธีที่ 2: HASH MAP (ระดับผ่านสัมภาษณ์ - ONE-PASS)
--------------------------------------------------------------------------------
- แนวคิด (Aha! Moment):
  เดินผ่านลิสต์ทีละตัว (num) แล้วถามว่า:
  "คู่ที่ขาดอยู่ (complement = target - num) เคยเดินผ่านมาแล้วหรือยัง?"
  * ถ้ามีอยู่ใน seen -> เจอคู่แล้ว ตอบทันที!
  * ถ้ายังไม่มี       -> จด {num: i} ลงใน seen ไว้รอตัวข้างหน้ามาจับคู่

[โค้ด Python (อ้างอิงคู่กับ hashMap.py)]
def two_sum(nums: list[int], target: int) -> list[int]:
    seen = {}                                # (1)
    for i, num in enumerate(nums):           # (2)
        complement = target - num            # (3)
        if complement in seen:               # (4)
            return [seen[complement], i]     # (5)
        seen[num] = i                        # (6)
    return []                                # (7)


5. อธิบายโค้ดทีละบรรทัด (LINE BY LINE)
--------------------------------------------------------------------------------
(1) seen = {}
  - สร้าง Dictionary ว่าง เก็บ {ค่าตัวเลข: index} ของตัวที่เคยผ่านมา

(2) for i, num in enumerate(nums):
  - enumerate() คืนค่าทั้งตำแหน่ง i และค่า num พร้อมกันในรอบเดียว

(3) complement = target - num
  - คำนวณหาคู่ที่ขาดอยู่ เช่น target = 9, num = 7 -> ต้องหา complement = 2

(4) if complement in seen:
  - ค้นหา key ใน dict ใช้เวลา O(1) (หัวใจที่ทำให้เร็วกว่า Brute Force!)

(5) return [seen[complement], i]
  - ดึง index ของตัวคู่เดิมจาก seen[complement] คู่กับ index ปัจจุบัน i แล้วส่งคำตอบ

(6) seen[num] = i
  - จดค่าปัจจุบันและ index ไว้ใน seen
  - [จุดพลาดยอดฮิต!] ทำไมต้องเช็กบรรทัด (4) ก่อน แล้วค่อยเก็บในบรรทัด (6)?
    กรณี nums = [3, 2, 4], target = 6:
    ถ้าเก็บ 3 ก่อนเช็ก พอคำนวณ 6 - 3 = 3 จะไปเจอตัวมันเองแล้วคืน [0, 0] ซึ่งผิดกฎ!
    การ "เช็กก่อนเก็บ" ช่วยป้องกันไม่ให้หยิบตัวเดิมซ้ำได้ 100%

(7) return []
  - วนครบทุกตัวแล้วไม่เจอคู่ที่บวกกันได้ target


6. การไล่การทำงานทีละก้าว (DRY RUN)
--------------------------------------------------------------------------------
ตัวอย่าง Input: nums = [2, 11, 7, 15], target = 9

  รอบที่ |  i  | num | complement (9-num) | อยู่ใน seen? | seen หลังจบรอบ
  -------|-----|-----|--------------------|--------------|-------------------------
    1    |  0  |  2  |         7          |     ไม่      | {2: 0}
    2    |  1  | 11  |        -2          |     ไม่      | {2: 0, 11: 1}
    3    |  2  |  7  |         2          | ใช่ (idx 0)! | return [0, 2] จบทันที!


7. เปรียบเทียบ BIG-O และแนวคิด TIME-SPACE TRADE-OFF
--------------------------------------------------------------------------------
[ประโยคทองในห้องสัมภาษณ์]
  "เราทำ Time-Space Trade-off โดยยอมใช้หน่วยความจำเพิ่ม O(n) สำหรับ Hash Map
   เพื่อลดเวลาทำงานจาก O(n^2) ลงเหลือ O(n)"

  วิธี         | Time Complexity | Space Complexity | ข้อมูล 100,000 ตัว (มากสุด)
  -------------|-----------------|------------------|-----------------------------
  Brute Force  |     O(n^2)      |       O(1)       | ~10,000,000,000 รอบ (ค้าง!)
  Hash Map     |     O(n)        |       O(n)       |         100,000 รอบ (<0.05s)


8. จุดเด่น ข้อจำกัด และการใช้งานจริงของ HASH MAP / HASH SET
--------------------------------------------------------------------------------
[จุดเด่น]
  + เพิ่ม / ค้นหา / ลบข้อมูล ใช้เวลาเฉลี่ย O(1)
  + ไม่ต้องเรียงลำดับข้อมูลก่อนใช้งาน
  + เป็นอาวุธหลักในการลดเวลาจาก O(n^2) -> O(n)

[ข้อจำกัด]
  - ต้องใช้หน่วยความจำเพิ่ม O(n)
  - key ต้องเป็นชนิดข้อมูลที่เปลี่ยนแปลงไม่ได้ (Hashable) เช่น int, str, tuple
    (ใช้ list เป็น key ไม่ได้ เพราะ list แก้ไขค่าได้)

[ตัวอย่างการใช้งานจริง / โจทย์สัมภาษณ์ที่พบบ่อย]
  - หาคู่ตัวเลข (Two Sum)
  - เช็กข้อมูลซ้ำ (Contains Duplicate -> ใช้ set)
  - นับความถี่ตัวอักษร/คำ (Valid Anagram -> ใช้ dict หรือ collections.Counter)
  - จัดกลุ่มข้อมูล (Group Anagrams -> ใช้ collections.defaultdict(list))
  - Caching / Memoization (จำผลลัพธ์ที่เคยคำนวณไว้)


9. EDGE CASES ที่ควรถามและเช็กในวันสัมภาษณ์
--------------------------------------------------------------------------------
  1) มีเลขซ้ำที่บวกกันได้ target: nums = [3, 3], target = 6
     -> รอบ 1: 3 ไม่อยู่ใน {} -> seen={3: 0}
     -> รอบ 2: 6-3=3 อยู่ใน seen! -> คืน [0, 1] (ทำงานถูกต้อง!)
  2) เลขครึ่งหนึ่งของ target แต่มีแค่ตัวเดียว: nums = [3, 2, 4], target = 6
     -> ต้องไม่คืน [0, 0] ต้องคืน [1, 2]
  3) มีเลขติดลบหรือเลข 0: nums = [-3, 4, 3, 90], target = 0 -> คืน [0, 2] (รองรับอยู่แล้ว)
  4) ลิสต์ว่างหรือมี 1 ตัว: nums = [] หรือ [5] -> คืน []


10. คำถามทบทวนความเข้าใจ (ลองตอบก่อนดูเฉลยด้านล่าง)
--------------------------------------------------------------------------------
Q1: ถ้าโจทย์ถามว่า "ในลิสต์ nums มีตัวเลขซ้ำกันหรือไม่ (True/False)"
    ควรใช้ dict หรือ set ดีกว่ากัน? เพราะอะไร?
Q2: ถ้า nums = [3, 3], target = 6 โค้ด two_sum แบบ Hash Map จะคืนค่าอะไร?
Q3: ใน Python เราใช้ list เป็น key ของ dict เช่น `d[[1, 2]] = "a"` ได้ไหม?
Q4: ทำไม `if complement in seen:` ถึงทำให้โค้ดลดจาก O(n^2) เหลือ O(n)?


--------------------------------------------------------------------------------
เฉลยคำถามทบทวน:
  A1: ใช้ set ดีกว่า เพราะเราต้องการรู้แค่ว่า "เคยเห็นค่านี้หรือยัง" ไม่ต้องเก็บ value เสริมอย่าง index
  A2: คืน [0, 1] (รอบแรกเก็บ 3:0, รอบสองเจอ 3 ตัวเดิมใน seen ที่ index 0 จึงคืน [0, 1])
  A3: ไม่ได้! จะเกิด TypeError: unhashable type: 'list' (ถ้าจะใช้เป็น key ต้องแปลงเป็น tuple ก่อน เช่น (1, 2))
  A4: เพราะการเช็ก `in` ใน dict ใช้เวลา O(1) แทนที่จะต้องวนลูปค้นหา O(n) ซ้อนในลูปนอก O(n)
