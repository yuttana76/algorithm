1. แนวคิดและหลักการของ BINARY SEARCH
--------------------------------------------------------------------------------
- แนวคิด: แทนที่จะไล่ตรวจทีละตัวเหมือน Linear Search เราจะตรวจ "ตรงกลาง" ก่อน
  แล้ว "ตัดพื้นที่การค้นหาทิ้งทีละครึ่ง" ในทุกๆ รอบ
- เปรียบเทียบชีวิตจริง: เกมทายเลข 1-100 โดยทาย 50 ก่อน ถ้าน้อยไปก็ตัด 1-50 ทิ้งทั้งหมด
  หรือการเปิดหาคำในพจนานุกรมจากกลางเล่ม

[กฎเหล็กสำคัญที่สุด!]
  *** ข้อมูลต้องเรียงลำดับแล้ว (Sorted) เท่านั้น! ***
  (เช่น เรียงจากน้อยไปมาก หรือ มากไปน้อย) ถ้าข้อมูลวางมั่วๆ จะตัดทิ้งทีละครึ่งไม่ได้

[ขั้นตอนการทำงาน 3 ก้าววนซ้ำ]
  1) กำหนดกรอบค้นหาด้วยตัวชี้ 2 ตัว: left (ซ้ายสุด = 0), right (ขวาสุด = len(nums) - 1)
  2) หาจุดกึ่งกลาง: mid = (left + right) // 2
  3) เทียบ nums[mid] กับ target:
     - เท่ากัน     -> เจอแล้ว! คืนค่า mid ทันที
     - น้อยกว่า    -> คำตอบอยู่ฝั่งขวาเท่านั้น ตัดซ้ายทิ้ง: left = mid + 1
     - มากกว่า    -> คำตอบอยู่ฝั่งซ้ายเท่านั้น ตัดขวาทิ้ง: right = mid - 1
  4) ทำซ้ำจนกว่าจะเจอ หรือกรอบหมด (left > right) -> คืนค่า -1


2. ตัวอย่างโค้ด PYTHON
--------------------------------------------------------------------------------
def binary_search(nums: list[int], target: int) -> int:
    left = 0                              # (1)
    right = len(nums) - 1                 # (2)

    while left <= right:                  # (3)
        mid = left + (right - left) // 2  # (4) (หรือ (left + right) // 2 ใน Python)

        if nums[mid] == target:           # (5)
            return mid                    # (6)
        elif nums[mid] < target:          # (7)
            left = mid + 1                # (8)
        else:                             # (9)
            right = mid - 1               # (10)

    return -1                             # (11)

# ทดลองเรียกใช้งาน (ลิสต์ต้องเรียงจากน้อยไปมาก!)
numbers = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91]
result = binary_search(numbers, 23)
print("เจอที่ตำแหน่ง (index):", result)  # Output: 5


3. อธิบายโค้ดทีละบรรทัด (LINE BY LINE)
--------------------------------------------------------------------------------
(1) left = 0
  - กำหนดขอบซ้ายสุดของช่วงที่ค้นหาเริ่มต้นที่ index 0

(2) right = len(nums) - 1
  - กำหนดขอบขวาสุดของช่วงที่ค้นหาเริ่มต้นที่ index สุดท้าย (มี 10 ตัว -> index 9)

(3) while left <= right:
  - วนลูปตราบใดที่กรอบการค้นหายังเหลือสมาชิกอย่างน้อย 1 ตัว
  - [จุดสำคัญวันสัมภาษณ์] ทำไมต้องมี <= ?
    เพราะตอนที่ left == right แปลว่าเหลือตัวเลขอีก 1 ตัวสุดท้ายในกรอบ
    เรายังต้องเข้าไปเช็กตัวนั้นก่อนจะสรุปว่าไม่เจอ

(4) mid = left + (right - left) // 2
  - หาตำแหน่งกึ่งกลาง โดย // คือการหารปัดเศษลงให้ได้จำนวนเต็ม
  - ใช้สูตร left + (right - left) // 2 เป็น Best Practice (ป้องกัน integer overflow
    ในภาษาอื่นอย่าง C++/Java และใช้ได้ดีมากใน Python)

(5)-(6) if nums[mid] == target: return mid
  - ถ้าค่าตรงกลางตรงกับเป้าหมาย คืน index ทันทีและจบฟังก์ชัน

(7)-(8) elif nums[mid] < target: left = mid + 1
  - ค่าตรงกลางยังน้อยกว่า target แปลว่าฝั่งซ้ายทั้งหมดรวมถึง mid เล็กเกินไป
  - ตัดทิ้งทั้งหมดแล้วขยับขอบซ้ายไปที่ช่องถัดจาก mid

(9)-(10) else: right = mid - 1
  - ค่าตรงกลางมากกว่า target แปลว่าฝั่งขวาทั้งหมดรวมถึง mid ใหญ่เกินไป
  - ตัดทิ้งทั้งหมดแล้วขยับขอบขวามาที่ช่องก่อนหน้า mid
  - [จุดพลาดยอดฮิต!] ทำไมต้อง + 1 และ - 1 ?
    เพราะเราเช็ก mid ไปแล้วว่าไม่ใช่ ถ้าเขียน left = mid หรือ right = mid
    อาจเกิด Infinite Loop (วนไม่รู้จบ) เมื่อกรอบแคบลงเหลือ 1-2 ตัว

(11) return -1
  - หลุดจากลูป while (left > right) แปลว่าตัดพื้นที่จนหมดแล้วไม่พบข้อมูล คืน -1


4. การไล่การทำงานทีละก้าว (DRY RUN)
--------------------------------------------------------------------------------
ตัวอย่าง Input: nums = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91], target = 23

  รอบที่ | left | right | mid | nums[mid] | เทียบกับ 23   | สิ่งที่ทำ
  -------|------|-------|-----|-----------|---------------|------------------------
    1    |  0   |   9   |  4  |    16     | 16 < 23 (น้อย)| left = 4 + 1 = 5
    2    |  5   |   9   |  7  |    56     | 56 > 23 (มาก) | right = 7 - 1 = 6
    3    |  5   |   6   |  5  |    23     | 23 == 23 (เจอ)| return 5 (จบการทำงาน!)


5. การวิเคราะห์ BIG-O และเปรียบเทียบกับ LINEAR SEARCH
--------------------------------------------------------------------------------
[Time Complexity - เวลาทำงาน]
  * Best Case  (กรณีดีที่สุด)  : O(1)      -> เจอตรงกลางตั้งแต่รอบแรก
  * Worst Case (กรณีแย่ที่สุด)  : O(log n)  -> หาร 2 ไปเรื่อยๆ จนเหลือ 1 ตัว (log ฐาน 2)
  * Average Case (กรณีเฉลี่ย)  : O(log n)

[Space Complexity - หน่วยความจำที่ใช้เพิ่ม]
  * O(1) (Constant Space) -> ใช้ตัวแปรแค่ left, right, mid (แบบ Iterative/while loop)
  * หมายเหตุ: ถ้าเขียนแบบ Recursion จะใช้ Space O(log n) จาก Call Stack

[ตารางเปรียบเทียบพลังของ O(n) vs O(log n)]
  จำนวนข้อมูล (n)     | Linear Search O(n) | Binary Search O(log n)
  --------------------|--------------------|-----------------------
  10                  |         10 รอบ     |          4 รอบ
  1,000               |      1,000 รอบ     |         10 รอบ
  1,000,000 (1 ล้าน)   |  1,000,000 รอบ     |         20 รอบ!
  1,000,000,000 (1 พันล้าน) | 1,000,000,000 รอบ |    30 รอบ!


6. จุดเด่น ข้อจำกัด และการใช้งานจริง
--------------------------------------------------------------------------------
[จุดเด่น]
  + เร็วมากระดับ O(log n) จัดการข้อมูลขนาดมหาศาลได้สบาย
  + ประหยัดหน่วยความจำ O(1)

[ข้อจำกัด]
  - ข้อมูลต้อง "เรียงลำดับแล้ว" เท่านั้น
  - ถ้าข้อมูลยังไม่เรียง การ Sort ก่อนใช้เวลา O(n log n):
      * ถ้าค้นหาแค่ครั้งเดียว -> ใช้ Linear Search O(n) คุ้มกว่า
      * ถ้าต้องค้นหาบ่อยๆ หลายครั้ง -> ยอม Sort ครั้งเดียวแล้วใช้ Binary Search คุ้มกว่ามาก
  - ต้องใช้กับโครงสร้างที่เข้าถึง index ตรงกลางได้ใน O(1) เช่น list/Array (ไม่เหมาะกับ Linked List)

[ตัวอย่างการใช้งานจริง]
  - ระบบ Index ในฐานข้อมูล (Database B-Tree Index)
  - คำสั่ง `git bisect` (ใช้หาว่า Commit ไหนที่เริ่มทำให้โปรแกรมมีบั๊ก)
  - โมดูลมาตรฐานของ Python: `import bisect`
      * bisect.bisect_left(nums, target)  -> หาตำแหน่งแทรกฝั่งซ้ายสุดใน O(log n)
      * bisect.bisect_right(nums, target) -> หาตำแหน่งแทรกฝั่งขวาสุดใน O(log n)


7. EDGE CASES ที่ควรถามและเช็กในวันสัมภาษณ์
--------------------------------------------------------------------------------
  1) ลิสต์ว่าง: nums = [], target = 5
     -> left = 0, right = -1 -> ไม่เข้า while (0 <= -1 เป็นเท็จ) -> คืน -1
  2) มีสมาชิก 1 ตัว: nums = [5], target = 5
     -> left = 0, right = 0 -> เข้า while ได้เพราะใช้ <= -> mid = 0 -> คืน 0
  3) target อยู่นอกช่วง (น้อยกว่าตัวแรก หรือ มากกว่าตัวสุดท้าย):
     -> เช่น nums = [2, 5, 8], target = 1 หรือ 99 -> สุดท้าย left > right -> คืน -1
  4) มีค่าซ้ำหลายตัวในลิสต์: nums = [1, 2, 2, 2, 5], target = 2
     -> Binary Search พื้นฐานจะคืนตำแหน่งไหนก็ได้ที่เจอก่อน (ไม่การันตีตัวแรกหรือตัวสุดท้าย)
     -> ถ้าโจทย์ขอ "ตัวแรกสุด" หรือ "ตัวสุดท้าย" ต้องปรับลูปไม่ให้ return ทันที (Lower/Upper Bound)


8. คำถามทบทวนความเข้าใจ (ลองตอบก่อนดูเฉลยด้านล่าง)
--------------------------------------------------------------------------------
Q1: ถ้า nums = [10, 3, 25, 7, 42] เอา Binary Search ไปหาเลข 25 เลยได้ไหม? เพราะอะไร?
Q2: ถ้าแก้เงื่อนไขจาก `while left <= right:` เป็น `while left < right:`
    แล้วใส่ nums = [5], target = 5 จะเกิดอะไรขึ้น?
Q3: ถ้าลิสต์เรียงจาก "มากไปน้อย" เช่น [90, 70, 50, 30, 10] ต้องแก้โค้ดตรงไหน?
Q4: ทำไมตอนสัมภาษณ์เห็นโจทย์ระบุว่า "Sorted Array" หรือ "O(log n)" ต้องนึกถึง Binary Search ทันที?


--------------------------------------------------------------------------------
เฉลยคำถามทบทวน:
  A1: ไม่ได้! เพราะข้อมูลยังไม่ได้เรียงลำดับ หากตัดทิ้งครึ่งหนึ่งอาจเผลอตัดฝั่งที่มี 25 ทิ้งไปได้
  A2: จะคืนค่า -1 (ผิด!) เพราะ left = 0, right = 0 ทำให้ 0 < 0 เป็นเท็จ จึงไม่เข้าลูปเลย
  A3: สลับเงื่อนไขเปรียบเทียบ:
      จาก `elif nums[mid] < target:` (ขยับซ้าย)
      เป็น `elif nums[mid] > target:` (เพราะเลขที่น้อยกว่าอยู่ฝั่งขวาของ mid แทน)
  A4: เพราะ Binary Search เป็น Algorithm มาตรฐานที่อาศัยคุณสมบัติความเรียงลำดับ (Monotonic)
      เพื่อลดเวลาค้นหาลงเหลือ O(log n)
